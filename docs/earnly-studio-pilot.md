# Earnly Studio private pilot

The owner-only preview stores prompts on the current device. It does not send them to Earnly or fal. On the Arcade origin the app can reuse Earnly authentication. Studio credits are isolated from coin wallets and VIP. No purchase flow is live.

## Activation order

1. Deploy the Studio migrations and functions to a test project. Verify that the media bucket is private, anonymous and authenticated roles cannot read Studio tables or execute their RPCs, and there are no broad pre-existing storage policies on that bucket.
2. Provision test accounts with studio_accounts.pilot and a small idempotent studio_grant from source pilot. The home link additionally checks auth app_metadata.studio_preview. Moderators require the server-managed app_metadata.studio_admin claim.
3. Use a dedicated prepaid fal account with auto-top-up disabled. Keep the *total available funds across the pilot* at or below $25. Confirm exact model prices, unit names, licenses and generation settings. Set studio_control.quote_expires for a short UTC pilot window. A missing or changed price disables further dispatch. Unexpected units need review. Never reinterpret per-second prices as per-video prices.
4. Provide worker secrets through the studio-private GitHub environment, populate its STUDIO_SUPABASE_URL variable and set repository variable STUDIO_PRIVATE_WORKER to enabled only after review. The worker also checks the database generation switch. A scheduler tick runs at most one reviewed submission and polls previously submitted jobs. GitHub schedules can be delayed. No schedule is active on a feature branch.
5. Enable studio_control only for a supervised real integration test. The initial daily maximum exposure is $0.50, monthly and fal maximums are $3.00, and the immutable aggregate ceiling is $25. Spend is conservatively tracked as **maximum exposure**. Reconcile billed cost from provider records before any paid or public launch. Rejecting a pre-dispatch job releases its reserve. For a possible dispatch retain its full exposure even on failure. Never retry a submission with an unknown outcome. Reconcile the provider receipt before resolving dispatching or uncertain records.
6. Sign in as the moderator and open earnly-studio-admin.html. Review each private prompt, approve or reject, and review each output before its creator can receive a signed URL. Pause stops new dispatch; accepted jobs may finish. Uploaded likenesses, public publishing, rewards and billing require additional verification.
7. A dedicated Studio ad unit is required. Set STUDIO_ADMOB_UNIT on the Studio function and configure the unit's SSV URL there. Price a credit against measured revenue and fund studio_ad_pool before enabling. The offer reserves credits up front. Unused tickets conservatively consume promotional pool capacity; reconcile expired unused tickets manually before replenishment. Existing arcade ad units are ineligible. The device callback never updates the wallet.
8. studio-commerce accepts sandbox Apple transactions using Earnly’s existing verification integration and a test-only Stripe webhook for a configured credit-pack price. Test purchases cannot buy paid inference. Subscription renewal/refund notifications, end-to-end storefront fulfillment, native Studio product selection, and payout reconciliation need integration tests before selling. Sandbox receipts and balances must never be promoted into live credits.

## Evidence

Run node scripts/test-earnly-studio.mjs for the isolated database and provider-price contracts. Run the existing commerce suite and the Studio browser spec. Real moderation quality, provider output, Apple product verification, AdMob settlement, independent-session load testing and physical iPhone playback are separate release checks. Do not label fixtures as live traffic.

The StoreKit bridge exposes Studio product IDs only in a build compiled with EARNLY_STUDIO_SANDBOX and a verified sandbox AppTransaction. Use studio/storekit-sandbox.js to verify restore/pending receipts before finishing. Studio production purchases have no enabled native product route. Personal likeness references are disallowed throughout the pilot. The worker re-encodes no user-supplied URLs. The authenticated upload endpoint re-encodes JPEG pixels and signs a private reference for an approved animation job.

Community is separately locked by studio_control.community_enabled and per-account community_eligible. Only enable after age eligibility, staffed moderation, prompt publication consent, blocking, report review and takedown have been exercised. The worker queues private object removal after account deletion and removes settled creations after 30 days. Keep the cleanup scheduler running while any pilot data is retained.
